Question: what tools should the Loom daemon expose over MCP (names, arguments, outputs, errors)? Proposed here: granular verbs mirroring the tracker-doc operations (create, view, list, comment, label, close, claim…) plus a few domain tools where the skills need atomicity (frontier, claim, append_to_section).

Everything runs in memory against a fake Loom. Two agent sessions (A, B) share it, both running as the single configured assignee sean, so you can see races. Click a tool name on the left to load it into free-play.
